# Internationalization (i18n)

Translations are split into **namespaces**:

| Namespace | Owner                    | File                                 | Contains                                                  |
| --------- | ------------------------ | ------------------------------------ | --------------------------------------------------------- |
| `common`  | core (default namespace) | `src/core/i18n/locales/<lang>.json`  | actions, shell, pager, theme, errors, validation, landing |
| `<id>`    | each feature             | `src/features/<id>/i18n/<lang>.json` | everything the feature displays                           |

Features contribute their namespace through the manifest (`i18n: { en, es }`). `app/i18n.ts`
registers them all.

## Using translations

Always import from the adapter:

```tsx
import { useTranslation } from '@/core/i18n/use-translation';

const { t } = useTranslation('tasks');         // this feature's namespace
t('page.title');
t('status.done');
t('detail.created', { date });                 // interpolation: "Created {{date}}"

const { t } = useTranslation(['tasks', 'common']);
t('new');                                      // first namespace
t('common:actions.cancel');                    // explicit namespace
```

Keys are **type-checked**: a typo is a compile error, and your editor autocompletes them. The
types come from `src/app/i18n-resources.d.ts`, which lists each namespace's English file.

Template keys work when every variant exists: ``t(`status.${task.status}`)``.

## Adding strings

1. Add the key to `en.json`.
2. Add the same key to **every other language**. The translations test fails otherwise:

   ```
   "tasks" has the same keys in "es" as in "en"
   ```

## Adding a language

1. Add it to `LANGUAGES` in `src/core/i18n/languages.ts`:

   ```ts
   { code: 'fr', label: 'Français' },
   ```

2. Create `fr.json` next to every `en.json`: `core/i18n/locales/` and each `features/*/i18n/`.
3. Import it in `core/i18n/i18n.ts` (`commonTranslations`) and in each manifest
   (`i18n: { en, es, fr }`).
4. Run `npm test`. The parity test lists any missing keys.

The language switcher and the settings page read `LANGUAGES`, so the new language appears
automatically.

## Detection and persistence

The language comes from `localStorage['zed-react:locale']`, then the browser. The fallback is
`VITE_APP_DEFAULT_LOCALE`. `<html lang>` updates on change.

## Dates and numbers

Format them with `shared/lib/format.ts` (dates) or `Intl.NumberFormat` (numbers), so the
formatting can follow the locale.
